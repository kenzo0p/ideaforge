# Deploying IdeaForge to Vercel

The app is a normal Next.js project, so Vercel works — with one caveat that this
guide solves: **Vercel's filesystem is read-only and ephemeral**, so a SQLite
*file* cannot be the database. We use [Turso](https://turso.tech), which is
libSQL — SQLite over the network. Same SQL dialect, so not a single query in the
codebase changed.

| | Local dev | Vercel |
|---|---|---|
| Database | `data/ideaforge.db` (a file) | Turso (`libsql://…`) |
| Telegram | long-polling, started by `instrumentation.ts` | webhook → `/api/agents/telegram` |
| Reminders | `setInterval` scheduler | Vercel Cron → `/api/cron/reminders` |

Both background loops are skipped automatically when `VERCEL` is set, so nothing
double-fires.

---

## 1. Create the database

```bash
brew install tursodatabase/tap/turso
```

```bash
turso auth signup
```

```bash
turso db create ideaforge
```

Grab the two values you'll need:

```bash
turso db show ideaforge --url
```

```bash
turso db tokens create ideaforge
```

The free tier (500 databases, 9 GB, 1 billion row reads/month) is far more than
a hackathon project needs.

## 2. Move your existing data over (optional)

Skip this if you're happy starting fresh — the schema is created automatically on
first boot. To keep the projects already in `data/ideaforge.db`:

```bash
sqlite3 data/ideaforge.db .dump > dump.sql
```

```bash
turso db shell ideaforge < dump.sql
```

## 3. Push to GitHub and import into Vercel

```bash
git add -A && git commit -m "Deploy: libSQL/Turso, webhook + cron for serverless"
```

```bash
git push
```

Then **vercel.com → Add New → Project → import the repo**. Framework detection
and build settings need no changes.

## 4. Set environment variables

In **Vercel → Project → Settings → Environment Variables** (Production +
Preview). Copy the values from your local `.env.local`:

**Required**

| Variable | Value |
|---|---|
| `TURSO_DATABASE_URL` | from `turso db show ideaforge --url` |
| `TURSO_AUTH_TOKEN` | from `turso db tokens create ideaforge` |
| `ANTHROPIC_API_KEY` | your key |
| `ANTHROPIC_MODEL` | `claude-sonnet-4-5` |

**Recommended** — each one degrades gracefully if missing, but the demo is much
weaker without them: `TAVILY_API_KEY`, `GITHUB_TOKEN`, `KAGGLE_API_KEY`,
`CORE_API_KEY`, `RESEND_API_KEY`, `EMAIL_FROM`, `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_WEBHOOK_SECRET`.

`CRON_SECRET` is generated by Vercel automatically once `vercel.json` declares a
cron — you don't set it, and `/api/cron/reminders` requires it as soon as it
exists.

> **Do not paste a value containing `#` or `$`.** In `.env` files an unquoted `#`
> starts a comment and `$name` is expanded as a variable, so the value silently
> becomes something shorter. (This exact thing had broken
> `TELEGRAM_WEBHOOK_SECRET` locally.) Stick to letters, digits, `_` and `-` —
> which is also all Telegram accepts for a webhook secret.

## 5. Deploy, then point Telegram at the webhook

After the first successful deploy, register the webhook once, replacing the
placeholders with your bot token, your Vercel URL, and your webhook secret:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<your-app>.vercel.app/api/agents/telegram&secret_token=<WEBHOOK_SECRET>"
```

Confirm it took:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo"
```

`url` should be your Vercel URL and `last_error_message` should be absent.

**Note:** once a webhook is registered, local long-polling stops working —
Telegram returns `409 Conflict`, which is exactly the error you'd see in
`npm run dev`. To go back to local development, delete the webhook:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/deleteWebhook"
```

## 6. Check the cron

`vercel.json` schedules `/api/cron/reminders` every 15 minutes. Verify under
**Vercel → Project → Cron Jobs** after deploying. On the Hobby plan crons run
once a day at most — if you need the 15-minute cadence for a live demo, either
upgrade or trigger reminders manually.

---

## Verifying the deploy

1. Sign up with a real email → the verification mail should arrive (Resend).
2. Run an idea through **Validate → Research → Plan** → **Save to dashboard**.
3. Reload. The project should still be there — that proves Turso is wired up. If
   projects vanish on reload, `TURSO_DATABASE_URL` isn't set and the app fell
   back to a throwaway file in the serverless sandbox.
4. Export a PPTX and open it.
5. Send `/projects` to the bot, then reply with a number.
